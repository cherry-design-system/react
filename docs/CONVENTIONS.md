# Component conventions (cherry 2.0)

Read this before adding a component. The reference implementations are `button`, `input` + `field`, `toggle`, `theme-toggle` and `toast` under `src/components/`, with their CSS in `src/styles/components/`.

## Files per component

```
src/components/<name>/
  <Name>.tsx          component(s)
  manifest.json       { name, class, attributes: { attr: [values] }, states, parts }
  variants.gen.ts     generated by `pnpm generate` (never edit)
  index.ts            named exports (component, props type, generated unions)
  <name>.test.tsx     tests (Vitest + Testing Library)
src/styles/components/<name>.css
```

`src/index.ts` is generated from the folders: never edit it. Run `pnpm generate` after adding or changing a manifest.

## Rules

- **CSS only, no CSS-in-JS.** All rules inside `@layer cherry { ... }`. No `!important`. JS never imports CSS.
- **Hooks:** root class `cherry-<name>`, parts `cherry-<name>__<part>`, variants and states as `data-*` attributes (`data-variant`, `data-size`, `data-invalid`...), ARIA attributes where they exist (`aria-expanded`, `aria-selected`, `aria-checked`, `aria-current`). Every manifest attribute value needs a `[data-attr="value"]` selector in the CSS (the contract check enforces it).
- **Tokens only.** Colors, spacing, radius, shadows, type and motion come from `--cherry-*` variables (see `src/styles/tokens.css`). Component-private variables are `--_name`. No hardcoded colors. Pixel sizes are fine for control geometry (32/36/44 heights, 16px icons).
- **No mode logic in components.** Tokens already switch for light/dark; never branch on the mode.
- **Props:** plain names (`variant`, `size`, `invalid`, `fullWidth`), no `$` prefix. Extend the native element's attributes, forward the ref with `forwardRef`, spread `...rest` onto the main element, merge `className` with `cx()`.
- **Server Components first.** No `"use client"` unless the component uses state, effects, context or event handlers it defines itself. Prefer native elements and platform features that need no JS: `<details>`/`<summary>`, `<dialog>`, the `popover` attribute, CSS anchor positioning, `:has()`, `<input type="range">`.
- **Errors only, no success state** on inputs (`invalid` prop + `data-invalid`). Use `useFieldControl` (from `../field/field-context`) so a control works inside `<Field>`.
- **Icons:** lucide only (`lucide-react`), imported per glyph.
- **Accessibility:** correct roles and names, keyboard support (arrows, Home/End, Escape where the pattern expects it), visible `:focus-visible` ring via `box-shadow: var(--cherry-ring)`, labels translatable through props.
- **Security:** never use `dangerouslySetInnerHTML` with caller input; sanitize nothing by hand; URLs from props go into `href` as given (React blocks `javascript:`).
- **Lowercase brand:** the product is "cherry".

## Motion (required)

Every element that changes state animates, consistently:

| Use                                                       | Duration                           | Easing                     |
| --------------------------------------------------------- | ---------------------------------- | -------------------------- |
| Hover, color, border, focus ring                          | `--cherry-duration-fast` (200ms)   | `--cherry-easing-standard` |
| Press feedback (`scale(.98)` buttons, `.94` icon buttons) | `--cherry-duration-instant`        | `--cherry-easing-standard` |
| Toggles, sliding indicators, thumbs, tabs underline       | `--cherry-duration-base`           | `--cherry-easing-spring`   |
| Overlays in (popover, menu, tooltip, dialog, sheet)       | `--cherry-duration-fast` / `-base` | `--cherry-easing-out`      |
| Overlays out                                              | `--cherry-duration-fast`           | `--cherry-easing-standard` |
| Deck / large layout moves                                 | `--cherry-duration-slow`           | `--cherry-easing-spring`   |
| Icon pops, emphasis                                       | `--cherry-duration-emphasis`       | `--cherry-easing-pop`      |

- Enter and exit both animate. For `popover` and `<dialog>`, use `@starting-style` plus `transition-behavior: allow-discrete` on `display` and `overlay` so the exit plays without JS. Popovers scale from `0.96` and fade, with `transform-origin` toward the anchor; dialogs fade + scale `0.96 -> 1`; sheets slide from their edge; backdrops fade.
- Accordion / disclosure height: `interpolate-size: allow-keywords` with `::details-content` transitions (`height`, `content-visibility` allow-discrete).
- Loading: Skeleton shimmer, Spinner rotate, typing dots bounce, Progress fill transitions width/transform.
- Use `transform` and `opacity` for movement; never animate `top/left/width` for movement.
- Keyframes are named `cherry-<component>-<what>`.
- `base.css` shortens all cherry animations under `prefers-reduced-motion: reduce`; add a component-level reduced-motion block when something should keep a gentler variant (see `spinner.css`).
- The toast (`toast.tsx`/`toast.css`) is the reference for choreography: staggered delays, an entry that waits for its container to land, a bump on in-place change.

## Verify

```bash
pnpm generate
pnpm typecheck           # whole project; errors in another component's folder are not yours
pnpm vitest run src/components/<name>
pnpm contract
```
